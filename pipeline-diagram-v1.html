CyberShield Pipeline

CyberShield detects attacks, quietly moves attackers into a honeypot, lets an AI agent investigate, and leaves every consequential decision to a human analyst. It is one pipeline for many attack types; SSH brute force is the first playbook.

  • Containment uses Wazuh Active Response, which is built in. No separate containment product.
  • Containment works in two stages: attackers trying to get in are redirected into a honeypot on the server; suspicious processes already running are cut off from the network and watched. Both are reversible and expire on their own.
  • The AI agent only reads and recommends. Blocks and account changes need an analyst.
  • The lab is three VMs: Wazuh, the victim server (real SSH + Cowrie + Suricata), and the attacker.

The complete pipeline

Eight stages, the same for every attack type. Each playbook only changes the sensor, the rule and the containment action.

Flagship playbook: SSH brute force

What happens, step by step, when someone starts guessing passwords.

Automatic (Wazuh, Suricata) Honeypot AI agent Human decides Attacker / danger

The story, step by step

  1. The attacker scans the victim server and starts guessing SSH passwords.
  2. Suricata sees the scan on the network. The server's SSH log records every failed login. The Wazuh agent ships both to Wazuh.
  3. Wazuh's rules sort what they see: nothing odd (just log it), an attack in progress, or an attacker who is already inside.
  4. For an attack in progress, Wazuh Active Response automatically runs our redirect script. It adds a firewall rule on the server so that this attacker's next SSH connection goes to port 2222 instead of 22, and closes their connections that are still guessing passwords. The rule removes itself after a set time. Everyone else still reaches the real SSH service.
  5. The attacker's next attempt lands in Cowrie, which is made to resemble the same server and accepts common default usernames with weak passwords. They think they've finally broken in. Every command and download is recorded and shipped back to Wazuh.
  6. The AI agent pulls everything about that IP from the Wazuh API: the scan, the failed logins, the redirect and the honeypot session. It builds one incident with a timeline, MITRE ATT&CK mapping and a confidence level, citing each log line.
  7. It recommends the next step: release (looks harmless), keep watching, block, or escalate.
  8. The analyst approves or rejects, seeing the evidence and the cost of being wrong.
  9. Wazuh carries out the approved action, for example a firewall block with a timeout, or lifting the redirect. Every step lands in the hash-chained audit log.

If they're already inside: when Wazuh sees a real login followed by suspicious activity (for example a password guessed before the threshold, or a stolen one), redirecting is too late. Their processes are cut off from the network at once while they keep running and stay watched; the SSH session itself stays up. The analyst then decides whether to disable the account (a built-in Wazuh action), freeze or kill the processes.

In one line: Wazuh contains, the AI investigates, the human decides.

Suricata's role

  • Early warning. It flags port scans before the password guessing starts, so a correlation rule can redirect a scanner sooner.
  • Sees beyond SSH. Web attacks, exploit attempts on other services, floods and unusual outbound traffic never appear in the SSH log.
  • Backs up the honeypot. When an attacker inside Cowrie tries to download malware, Suricata sees the network side of it.
  • Benchmark. CIC-IDS2017 recordings are replayed through Suricata to test the agent on public data.
  • Blind spot. SSH is encrypted, so Suricata can't read what attackers type. That's Cowrie's job.

Guardrails on the automatic redirect

  • Clear trigger: e.g. 5 failed logins within a minute, logins to usernames that don't exist, or a scan followed by failures.
  • Allowlist: admin and monitoring IPs are never redirected; they raise an alert instead.
  • Auto-expiry: the redirect is a stateful Active Response, so Wazuh removes it after the timeout. While the analyst hasn't decided yet, it is held up to a hard cap.
  • Logged-in sessions are never cut. New connections move to the decoy, and connections still guessing passwords are closed.
  • Analyst notified immediately, with one-click release.
  • Honeypot locked down: Cowrie runs as an unprivileged user, and port 2222 is closed to anyone who hasn't been redirected.

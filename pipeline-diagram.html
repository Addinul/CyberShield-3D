CyberShield Pipeline

CyberShield detects attacks, quietly moves attackers into a honeypot, lets an AI agent investigate, and leaves every consequential decision to a human analyst. One pipeline covers many attack types; each attack type plugs in as a playbook.

How it works as one system

CyberShield is not a set of tools that someone starts and connects one by one. Once the lab is running, one loop runs by itself. The only thing a person does is approve or reject.

One collector

A small Wazuh agent on each machine gathers what every sensor sees and sends it to one place. Nobody copies logs from tool to tool.

Instant reflexes

When Wazuh recognises an attack, it reacts within seconds: it redirects the attacker or cuts a process off from the network. These reflexes never wait for the AI, and they undo themselves.

One coordinator

The orchestrator receives every alert as it happens. It groups alerts from the same attacker into one incident, waits for the burst to settle, then asks the AI once. It follows each incident until it is closed.

One click

The analyst sees one card per incident, with the evidence and a recommendation. One click approves or rejects it, Wazuh carries it out, and every step is written to a log that shows any tampering.

Playbook: SSH brute force and break-in

Phase 1 · flagship

Someone guesses passwords on a real server. They are moved into the honeypot before they can get in, and judged by what they do there.

Playbook: web application attack

Phase 2

Someone tries SQL injection on a web app, then plants a web shell. The probing alone only raises an alert; a shell started by the web server is cut off at once.

Playbook: malware downloaded and run

Phase 2

A file is downloaded and run on a server. It keeps running, but it cannot call home or send data out while the analyst decides.

In one line: Wazuh contains, the AI investigates, the human decides.

Guardrails on automatic containment

  • Clear triggers: signals genuine users rarely produce, such as 5 failed logins within a minute, logins to usernames that don't exist, or a program running from a temporary folder.
  • Allowlist: admin and monitoring addresses and critical services are never contained automatically; they raise an alert instead.
  • Time limits: both automatic actions undo themselves after a timeout. While the analyst decides, the orchestrator extends them up to a hard cap.
  • Logged-in sessions are never cut. New connections move to the decoy, connections still guessing passwords are closed, and isolation cuts only the network.
  • Rule floors: evidence such as a download attempt sets a minimum confidence that text typed by an attacker cannot talk the AI below.
  • Honeypot locked down: Cowrie runs as an unprivileged user, and its port is closed to anyone who hasn't been redirected.
